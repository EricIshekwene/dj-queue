# R2-SCREENS decisions

## PIPELINE (Score · Edit · Queue)

- **Score Single is drawn by the screen (DSVideoPreview + DS pieces), not ClipCollection's Single.** Why: §6.1 puts the control pill and key hints *under the player* and a progress strip above it; ClipCollection's Single has no slot below the player.
- **The Score field is a key-driven box (focusable view + `onKeyPress`), not a native text field.** Why: a text field swallows ←/→ and ⇥, and the spec needs digits, ↩ save & next, ⇥ skip, ←/→ previous/next and ⌘⌫ exclude to work while it has focus.
- **Save & next hides the clip at once (optimistic) and saves through BulkActions.setScore with an undo toast ("Scored 72 · Undo").** Why: scoring must feel instant; the hidden id is forgotten as soon as the refresh drops it, so Undo brings the clip back.
- **Progress strip = clips in the sets that still have something to score ("46 of 59 scored").** Why: "17 of 29" (spec) is per scoring run; the sets being scored are the natural run, while the whole library would never move.
- **Kind on Score Single uses `model.setKind` (no toast); Exclude goes through BulkActions (undo toast).** Why: Kind is a reversible toggle shown in place; Exclude removes the clip from the list, so it needs Undo.
- **Score Grid is drawn by the screen (DSClipCard `.grid` + an inline field under each tile).** Why: tile actions in ClipCollection only appear on hover over the cover; the score field must always be visible under the tile.
- **Typing a valid score in a grid tile selects that tile.** Why: the bulk bar (with **Save scores**) only shows for a selection; selecting what you typed is the least surprising way to surface it.
- **"Save scores" saves each typed value without a confirmation sheet; clips sharing a value share one batch; the toast's Undo reverts every batch (⌘Z the last).** Why: each score is Eric's explicit per-clip choice (nothing implicit to confirm), and BulkActions.setScore takes one value per batch.
- **Score grid "More": ±1 / ±10 adjust the typed (unsaved) scores of the selection.** Why: Score clips are unscored, so BulkActions.adjustScore would skip them all.
- **Bulk bars keep at most three labelled actions + More + a short primary.** Why: the DS bar is capped at 720 pt; with "N selected · Select all" the spec's four actions + full primary labels overflowed and wrapped. Edit: Top title · Caption ▾ (template + hashtags sections) · Kind ▾ · More · **Make ready**. Queue: Pin to days… · Post today · More (Skip platform ▸, Exclude, …) · **Add to week**. Score: Set score… · Kind ▾ · Exclude · More · **Save scores**.
- **Bulk-bar menus show "Title ⌄" without a leading icon.** Why: the chevron marks them as menus and saves the width the bar needs.
- **Edit's toolbar "Make ready with defaults" turns outlined while something is selected.** Why: the bulk bar then carries the near-black primary for the same action — one filled button per screen.
- **Edit filters are single-select chips built from `issuesByVideo` (missing pieces first, then hard blocks, platform order); clicking the active chip clears it.** Why: matches `All 9 · No crop 4 · …`; one filter at a time keeps "Make ready" (acts on the filtered clips) unambiguous.
- **Edit cards put title help, fixes and Open editor in a right-hand column (the card's action slot): [Add title | Ask an agent] · up to two fixes · [Open editor] [⋯]; further fixes live in ⋯.** Why: DSClipCard's chip row can't host controls and the card is a fixed 132 pt.
- **Suggestion chips on Edit Cards/Grid show only the suggestion text; the matched tracks show in Single and the editor.** Why: with tracks, three chips wrap past the 132 pt card.
- **Edit Grid shortens danger chips to "Too long for X"; Edit List rows show what's missing as their second line instead of the session.** Why: tiles truncate the numbers mid-chip, and list rows have no chip row at all.
- **"Add title" rests as a quiet field-shaped box and becomes a real text field on click; ↩ = BulkActions.setTitle (undo toast), esc/blur with nothing typed restores it.** Why: a live text field on every card made the window auto-focus the first one (loud focus ring on load); still never prefilled.
- **Fixes: "Trim for X" and "Write an X caption" open the editor; "Drop hashtags for X" runs BulkActions.dropHashtags and is disabled (with the reason) when the caption has no hashtags or is still too long without them.** Why: explicit actions only, and a disabled control says why.
- **"Cover" badge = `Edit.coverTime` set (read per refresh for the clips shown).** Why: AppModel caches no edits; a handful of reads per refresh is cheap.
- **Queue Cards are drawn by the screen (DSClipCard `.wide` in a LazyVStack).** Why: Queue needs drag-and-drop and hover-only actions; ClipCollection keeps its hover state private and has no drop hooks.
- **Drag to reorder = drop on a *planned* clip → the dragged clip takes that day, pinned (BulkActions.pinConsecutive, undoable); dropping on a backlog card explains that the backlog follows the sort.** Why: the core has no free reorder API (backlog order = score sort + skip-next); pin is the core's way to place a clip on a day and it is journaled. No core code added.
- **Single-clip Post today / Pin / Exclude / Kind go through BulkActions too.** Why: every write from these screens gets the same "· Undo" toast.
- **Pin to date… / Pin to days… use one in-screen dialog (graphical calendar, scrim) instead of a popover.** Why: grid and list hover actions disappear when the pointer leaves, which would close an anchored popover; the dialog also serves the bulk "Pin to days…".
- **"Add to week" targets the first week from today with a free day.** Why: this week is usually full (approved); BulkActions.addToWeek fills one week and skips the rest with the reason in the sheet.
- **Queue Grid shows the next day as an outlined tag (pin glyph when pinned).** Why: grid tiles have no date chip, and the next date is the Queue's key fact.
- **Queue sort menu writes `Settings.sort` and lists the tie rule and "planned clips keep their days" as inert menu text.** Why: the order only applies to the ready backlog; the plan keeps its dates.
- **Queue hover actions in Cards/List are icon buttons (Post today, Pin to date…, ⋯) with tooltips; Single shows labelled buttons.** Why: the 880 pt card already carries platform icons, the date chip and the score.
- **Snapshot extras (one unscored, untitled clip scored 26 so "Add title"/"Ask an agent" show on Edit; a cover on the too-long clip) are applied by the Edit shots and reverted by the Queue shots.** Why: the seed has no Edit clip without suggestions; reverting keeps other leaves' shots on the plain seed.
